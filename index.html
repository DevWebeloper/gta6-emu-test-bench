    Blockers and fixes

    4 fixed, 4 worked around, 2 still open.

    investigatingperf

    trustno1: GPU time jumps 40 -> 135 ms/frame after ~3 min in-game

    Not card steps, not throttling; VICTORY_GPU_TIMING run to name the pass.

    openperf

    Frame preparation is CPU-bound (copies + texture uploads)

    Open: 57-90 ms/frame preparing on the CPU.

    workarounddriver

    Windows TDR (2 s) kills multi-second cold-cache frames

    TdrDelay=10 set by the user (fork's own test PC uses the same).

    workaroundGPU

    GPU hang (device removed) on cold pipeline cache

    Did not recur with a warm pipeline cache (DRED run 12:42).

    workaroundSeries S

    Menus black on Series S (forkamd)

    Forks with VICTORY_COMPOSE lay the interface plane over the game.

    workaroundinput

    Legal Notices screen on a fresh data folder

    Data folder copied from an earlier run so the screen is skipped.

    fixedsetup

    Game executable missing from the test folder

    User put the exe in place; launches since then.

    fixedSeries S

    FSR4 refuses 806x453 render size (black screen #1)

    Series S keeps the title's own 2/3 scale (forkamd 0e4fa86).

    fixedSeries S

    FSR4 passes are console-only GPU code (black screen #2)

    Title's own upscaler (VICTORY_UPSCALER / VICTORY_OWN_UPSCALER) instead of FSR4.

    fixedinput

    Start screen waits for a button press

    Scripted pad presses (VICTORY_KEYS) in the harness.

    Method

    How we test

    Same machine, same game files, same script for every fork, so the numbers can be compared with each other. They are not comparable with the forks' own claims on bigger GPUs.

    1. 1

      Build

      Each fork is built on the laptop from its own source code.

    2. 2

      Run

      One scripted run per setting on the same laptop and game dump: launch, scripted button presses to get past the start screen, then 2.5 to 15 minutes of play.

    3. 3

      Measure

      Every number comes from the emulator's own log: frames per second, CPU and GPU time per frame, draws, video memory.

    4. 4

      Best minute

      The best 60-second median fps after the game world first renders (more than 1,000 draws a frame). Peaks and menus do not count.

    5. 5

      Graphics

      Ray tracing is read from the log (whether the ray-tracing structure builder runs). Asset loading is how long textures take to sharpen, how many wait for video memory, and how many draws still wait for shaders.

    6. 6

      Screenshots

      Only frames from runs cleared for publishing are shown, cropped to the game window.
